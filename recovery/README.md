# TWRP для balmunlock

Закреплённый образ: `TWRP-3.7.1_12-BALMUDA_Phone-20261024.img`, 100663296 байт.

SHA-256: `9d19aeaac7b6f96d00fa4745f7cdc3642b2a06988124c8859d2f59f0d604a6f7`.

Положите образ в эту папку. Бинарный файл исключён из Git. Альтернативный путь
можно передать через `--install-recovery --recovery-image PATH`; произвольный
образ с другим хешем не допускается. `--check-recovery-image` проверяет образ
без ADB/USB. Фиксированный [архив TWRP](https://github.com/glebn2/balmunlock/releases/download/v0.5.0/TWRP-3.7.1_12-BALMUDA_Phone-20261024.zip)
содержит образ, SHA256SUMS, инструкцию и список изменений. SHA-256 архива:
`ca82e56feb5d3e835d318cf06940e50fb3408aefaac8fa49299bec7294d5f1d2`.
Сетевой загрузки во время установки нет. Windows-сборщик умеет получить этот
архив через `--recovery-archive-url` и проверяет оба хеша.

Допуск автоматической установки: штатный A101BM, Android 12,
`1.280PO.0686.a`, активный слот b, загрузчик разблокирован. Сравнение аппаратной
основы X01A не заменяет испытания; автоматическая запись на X01A не разрешена.

TWRP 3.7.1_12-BALMUDA_Phone (20261024) использует штатные ядро, DTB и recovery DTBO.
По журналам испытаний порта на A101BM проверены расшифровка стока без PIN и с PIN,
LineageOS с PIN/узором, ADB/MTP, sideload/ZIP, бэкап и восстановление,
fastbootd, стирание/форматирование и возврат Android. Полный новый автоматический
сценарий balmunlock на телефоне ещё не проверен. X01A остаётся непроверенным.
Подробнее: [инструкция](INSTALL.md), [изменения](CHANGELOG-20261024.md).
Источники самого порта и его поддержка ведутся отдельно от кода balmunlock;
наличие образа здесь не означает полного комплекта исходников TWRP.

Установщик сохраняет предыдущий recovery_b в отдельный каталог
`recovery-sessions/device-…/<UTC>-<id>/`. Сохраняются образ для установки,
сырой бэкап предыдущего раздела, SHA-256, журнал и `state.json`. Если до
установки стоял кастомный recovery, бэкап содержит его, а не заводской образ.
Старые каталоги никогда не перезаписываются. Бэкап требует отдельной копии на
другом носителе; автоматически созданная копия рядом с программой не защищает
от отказа диска ПК.

Сценарий: подтверждение пользователя → bootloader/unlocked/слот/снимки/размер →
временный TWRP → сверенное чтение старого recovery_b → повторная проверка
загрузчика → запись recovery_b → загрузка установленного TWRP → SHA-256 раздела →
возврат штатного Android. Если тот же TWRP уже установлен, запись пропускается.
Во время записи Ctrl+C откладывается; fastboot flash не прерывается таймером.
При ошибке нет автоматического повторного flash, восстановления или смены слота.

После ошибки сохраните весь каталог сеанса и установите фактический режим
телефона. При рабочем bootloader, том же serial, подтверждённых unlocked=yes,
is-userspace=no и current-slot=b сохранённый сырой бэкап может быть кандидатом
для ручного `fastboot -s SERIAL flash recovery_b BACKUP.img`. Сначала сверить
размер/хеш с журналом. Аппаратное испытание такого восстановления не выполнено.
`--recover` по-прежнему относится к служебному восстановлению после анлока;
это не команда отката TWRP.
