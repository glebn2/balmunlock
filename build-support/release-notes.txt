balmunlock 0.6.0 — TWRP in the active slot

TWRP installation and updates now automatically select recovery_a or recovery_b
from the running Android slot. Both option 2 (TWRP only) and option 3 (unlock +
TWRP) use the same slot binding. No manual slot selection or slot switching.

The slot is bound before confirmation and checked again in bootloader and TWRP.
Backup, partition-size checks, flashing and SHA-256 readback all use the same
partition. A missing/invalid suffix or a slot change stops the operation.
The other recovery partition is untouched; identical images are not reflashed.

Slot b installation was tested on A101BM. Slot a support is host-tested with
independent simulated recovery_a/recovery_b partitions; no slot a hardware test
is claimed. This does not modify super or prepare logical partitions for LineageOS.

Unlocking retains the stock Android 12 / 1.280 policy. Recovery installation
also works from custom Android, including LineageOS. It completes in TWRP;
choose Reboot -> System to boot Android. Retain sessions/ and recovery-sessions/.

Bundled TWRP is unchanged: 3.7.1_12-BALMUDA_Phone (20261025), image SHA-256:
9e4d0c0707d83a6a3d5ec3fcad4c2f3296996348603817163540ddad7a840702

The ZIP contains only the utility, runtime dependencies, USB driver preset and
recovery image. Documentation, changelogs, source ZIPs and build metadata stay out.
