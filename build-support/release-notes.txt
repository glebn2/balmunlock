Unmuda 0.2.0 — guided setup and saved-session continuation

Windows x64: extract the complete ZIP into a writable folder, open PowerShell there and run .\unmuda.exe. Python, USB libraries and Android Platform-Tools are included. Keep _internal, platform-tools and tools beside the EXE. Linux: use Source code and the Linux README section.

What changed:
- In a terminal, setup stays in the same window: authorize ADB or install the indicated WinUSB driver, then enter yes to check again. DIAG probing is read-only and distinct from partition operations.
- Existing backups are handled as a saved session. Prepared sessions can continue, interrupted sessions offer recovery, and completed unlocks are reported without device access or repeat writes.
- After a completed rollback, a confirmed retry reuses the originals only after validating device identity and complete live partition contents.
- If a receipt is missing, rebuilding it requires valid local backups and two complete matching live reads; it never writes the partition during inspection. Corrupt/ambiguous files cannot be accepted by confirmation.
- Pending Android-setting cleanup is explained and performed on the original device. unmuda-last-error.txt records diagnostic details.
- Unknown bootloader mode does not permit recovery flashing. Cancellation and existing write protections remain in place.

Normal terminals enable guided prompts automatically. --guided explicitly enables them with redirected input; --non-interactive keeps strict stop-on-error behavior. An ordinary launch offers the appropriate recovery action; --recover remains available.

Upgrading from 0.1.0: extract the whole new archive, copy all chkcode_backup* files and cve_cleanup.device.json (if present) into the new directory to continue that session, and retain the old directory. Do not overwrite/delete originals or regenerate checksums to bypass validation. Use a separate directory for another phone.

Unlocking erases user data. The source workflow completed an unlock on A101BM 1.280PO.0686.a under Windows, and the earlier EXE's refusal of an already unlocked bootloader was verified on a phone. The new guided flows have offline regression/frozen-EXE coverage; a complete 0.2.0 hardware unlock and hardware failure rollback remain unverified. The EXE is not digitally signed.

The ZIP includes third-party notices and corresponding libusb sources. Original method and Kyocera research: E2r7hN07Fl47/unmuda. Fork: glebn2/unmuda, with GPT-6.1 Sol assistance. GPL v3 is retained.
